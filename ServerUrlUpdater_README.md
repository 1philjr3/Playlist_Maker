# Автоматическое обновление URL сервера в приложении

Данная инструкция поможет вам настроить механизм автоматического обновления URL сервера в приложении Android для работы с внешним доступом через ngrok.

## Проблема

В Android-приложении жестко закодирован URL сервера (`localhost`, `10.0.2.2` и т.д.), что не позволяет подключаться к серверу через интернет с помощью ngrok.

## Решение

1. Добавлены специальные API-эндпоинты на сервере для предоставления публичного URL
2. Создан механизм автоматического обновления URL сервера в приложении

## Шаги по внедрению

### 1. Добавьте класс ServerUrlUpdater.kt в ваш проект:

Скопируйте файл `ServerUrlUpdater.kt` в пакет `com.practicum.playlist_maker.network` вашего проекта.

### 2. Обновите класс App или MainActivity:

```kotlin
// В классе App.kt или MainActivity.kt добавьте:
import com.practicum.playlist_maker.network.ServerUrlUpdater

// В методе onCreate:
ServerUrlUpdater.updateServerUrl(this) { serverUrl ->
    if (serverUrl != null) {
        Log.d("App", "Сервер доступен по адресу: $serverUrl")
    } else {
        Log.e("App", "Сервер недоступен")
        // Можно показать сообщение пользователю
    }
}
```

### 3. Добавьте проверку при запуске активити:

```kotlin
// В основной активити или фрагменте, который взаимодействует с сервером:
private fun checkServerConnection() {
    ServerUrlUpdater.updateServerUrl(requireContext()) { serverUrl ->
        if (serverUrl == null) {
            // Сервер недоступен, показываем ошибку
            showErrorMessage("Сервер недоступен. Проверьте соединение с интернетом.")
        }
    }
}

// Вызовите этот метод в onResume() или при создании активити
```

## Как это работает

1. **В начале работы приложения**:
   - Проверяется, есть ли сохраненный URL сервера в SharedPreferences
   - Если есть, проверяется его доступность
   - Затем проверяется, не предоставляет ли сервер публичный URL через ngrok
   - Если публичный URL доступен, он сохраняется и используется для всех запросов

2. **В случае недоступности сохраненного URL**:
   - Перебираются все локальные URL (localhost, 127.0.0.1, 10.0.2.2)
   - Для каждого доступного сервера проверяется наличие публичного URL
   - Найденный URL сохраняется в SharedPreferences

3. **В случае смены URL ngrok** (при перезапуске сервера):
   - При следующем запуске приложение обнаружит, что сохраненный URL недоступен
   - Будет выполнен поиск нового URL, включая публичный через ngrok
   - Новый URL будет сохранен и использован

## Проверка работы

1. Запустите сервер с туннелем: `npm run tunnel`
2. Запустите приложение на устройстве с доступом в интернет (не подключенном к локальной сети)
3. Приложение должно автоматически обнаружить публичный URL и начать использовать его

## Важно!

- Сервер должен быть запущен с туннелем ngrok для доступа из интернета
- Если сервер перезапускается, URL ngrok меняется, и приложение автоматически обновит его при следующем запуске
- Если вы используете платную версию ngrok, вы можете настроить постоянный поддомен, чтобы URL не менялся

## Альтернативный подход (через push-уведомления)

Если ваше приложение использует Firebase Cloud Messaging (FCM), можно настроить отправку push-уведомлений с новым URL сервера при его перезапуске:

1. При запуске сервера отправлять всем зарегистрированным устройствам push-уведомление с новым URL
2. В приложении добавить обработчик таких уведомлений для обновления URL в SharedPreferences

Это позволит автоматически обновлять URL даже когда приложение не запущено.
